## Protocol findings

| Question | Evidence and implementation decision |
| --- | --- |
| Discovery, pairing and authentication | Camera Wi-Fi and Bluetooth advertising are separate entry points. An advertisement name is a discovery hint. A CoreBluetooth central connection alone cannot establish Nikon application authentication. Use Nikon's user-approved pairing procedure as the field reference. Capture firmware, model, pairing state and prompts before attempting a model-specific adapter. [Nikon Z8 wireless connections](https://onlinemanual.nikonimglib.com/z8/en/wireless_connections_86.html) |
| Wi-Fi activation and joining | A camera can present an SSID and password through its menu. The app can apply an explicitly entered configuration with system approval or use an already joined network. The Android Z5 report does not establish a portable BLE activation command. [Nikon direct Wi-Fi](https://nikonimglib.com/snbr/onlinehelp/en/direct_wifi_connection_5.html) · [Apple hotspot configuration](https://developer.apple.com/documentation/networkextension/nehotspotconfigurationmanager) |
| PTP/IP | Bind command and event sockets by the responder connection number. Keep exactly one reader per socket, service event probes, and correlate every data/response packet by transaction. AeroShutter labels the direction values differently from libgphoto2 and ZENCHE. We use 1 for no-data or camera-to-initiator reads, agree with both native implementations, and check the bytes in a golden-vector test. [CIPA transport paper §2.3.6](https://www.cipa.jp/std/documents/e/DC-X005.pdf) · [libgphoto2 sender](https://github.com/gphoto/libgphoto2/blob/6d5c61ef7687b74fe792e4aeae7fc40f2ad42d88/camlibs/ptp2/ptpip.c) |
| Card, list and thumbnail | GetStorageIDs → GetObjectHandles → GetObjectInfo yields object identity and size. GetThumb transfers a separate preview. Traverse by card and skip association entries. Check per-camera behavior with empty, multiple and large cards. [AeroShutter client](https://github.com/subhashraveendran/aero-shutter-mobile/blob/03cda84cc2c85ae5ad4e352105cfb3140e360be8/src/lib/ptpip/client.ts) |
| Originals and Nikon extensions | GetObject can transfer the original bytes of an exposed object. NEF/video visibility, format codes and size reporting are model/mode dependent. LargeThumb and extended partial-read identifiers are recorded for research. Validate DeviceInfo operations, file metadata and actual response before enabling any vendor operation. [Nikon operation identifiers](https://github.com/gphoto/libgphoto2/blob/6d5c61ef7687b74fe792e4aeae7fc40f2ad42d88/camlibs/ptp2/ptp.h) |
| Resume and large files | GetPartialObject supports offset-based requests on some devices. Reusing a handle after reconnection risks reading a different object. The prototype keeps partial data, compares responder/card/handle/name/size/capture time on reconnect, then starts GetObject again at zero. Validate range reads against a card-copy hash before enabling byte resume. Unknown/extended ObjectInfo sizes require a separate path. [Upstream partial-read implementation](https://github.com/subhashraveendran/aero-shutter-mobile/blob/03cda84cc2c85ae5ad4e352105cfb3140e360be8/src/lib/ptpip/client.ts) |

## Experiment · Upload While Off

The Nikon Z8 manual describes continued transfers with the camera's power switch off for Bluetooth or a Wi-Fi access point connection. Nikon documents AP and STA options separately. Record the exact menu wording, role and firmware for each run. The power switch position alone cannot establish which radios remain energized. SnapBridge also applies camera- and link-specific restrictions to automatic upload, image size, RAW visibility and movies. [Z8 network menu](https://onlinemanual.nikonimglib.com/z8/en/nwm_connect_to_smart_device_358.html) · [SnapBridge selected downloads](https://nikonimglib.com/snbr/onlinehelp/en/02_transfer_03.html)

Test with a small JPEG already queued, a new JPEG, then an NEF as separate trials. Record switch-off timing, queue origin (camera or phone), whether BLE advertising or an established link persists, whether the previously open TCP session survives, and whether a fresh user-approved connection is possible. Repeat for camera AP and infrastructure Wi-Fi, foreground and locked phone. Compare saved objects with the card and record file size, digest and battery change. Distinguish a queued derivative from an original. Leave BLE wake and off-state RAW disabled until repeatable results identify supported firmware and a documented or authorized interoperability path.

iOS background Bluetooth delivery is event-driven. Background scanning may coalesce discoveries and restoration requires an explicitly configured central. It supplies no general entitlement to run an arbitrary Wi-Fi transfer indefinitely. The prototype runs in the foreground. Bluetooth background modes and restoration require physical-device experiments. [Apple background Bluetooth](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html)

## Distribution decision

Use MIT for PixelBridge project contributions. The runtime contains Apple frameworks, project code, the adapted MIT packet helpers and a generated test-pattern JPEG. The iOS Settings screen exposes the upstream notice. The lab image is generated from FFmpeg's testsrc2 filter and contains no photographer's images. XcodeGen regenerates the checked-in build project and is a development tool. Reassess notices and obligations before adding a native library or a vendor binary.
